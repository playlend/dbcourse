Milestone 2 · Buffer Pool Manager

Put a concurrent cache in front of the disk: fixed 8 KB frames, a page table, RAII read/write latch guards, CLOCK eviction (with LRU-K as a stretch goal), and hit-rate telemetry — from this milestone on, every page in FerricDB flows through it.

Milestone 1 gave FerricDB durable storage with the performance profile of a filing cabinet: one disk round trip per page touch. This milestone builds the memory-management layer that sits between every access method (heap files, catalog tables, B+Trees) and DiskManager. It is also the first piece of real concurrent systems code in the course. Eight threads will hammer a tiny eight-frame pool simultaneously under ms2_stress_multithreaded: if your lock order can invert, if a pin count drifts by one, or if a dirty victim slips past write-back, that test will catch it. Budget a full weekend, design the latch protocol on paper before writing a line of Rust, and let the provided suite verify every invariant.

Learning objectives

  • Implement a fixed-size buffer pool managing pool_size 8 KB frames, a page table mapping PageId to FrameId, hit/miss counters, and miss handling over Milestone 1's DiskManager.14
  • Implement two-tier safe-Rust latching with RAII pin guards (ReadPageGuard and WritePageGuard), permitting concurrent readers on a single page and guaranteeing zero aliasing undefined behavior and zero leaked pins.15
  • Enforce a strict lock-acquisition and drop ordering between pool metadata and per-frame RwLocks so ABBA deadlocks are impossible by construction.3
  • Implement the CLOCK (second-chance) replacement policy behind the Replacer trait, and optionally LruKReplacer (backward k-distance) as a stretch goal.23
  • Enforce write-back dirty tracking and the dormant LogFlusher WAL-rule call site so Milestone 9's write-ahead log slots in without rewriting eviction or flush paths.14
  • Measure cache hit rate and fetch throughput on a working set larger than the pool using Criterion, and wire the pool into the REPL.4

// crates/buffer/src/lib.rs — verbatim public API from api-spec.md

pub trait Replacer: Send {
    fn record_access(&mut self, frame: FrameId);
    fn set_evictable(&mut self, frame: FrameId, evictable: bool);
    fn evict(&mut self) -> Option<FrameId>;
    fn evictable_count(&self) -> usize;
}

pub struct ClockReplacer { /* ref bits + hand */ }
impl ClockReplacer { pub fn new(num_frames: usize) -> Self; }

pub struct LruKReplacer { /* stretch: history of last K accesses */ }
impl LruKReplacer { pub fn new(num_frames: usize, k: usize) -> Self; }

/// Log hook for the WAL rule (Milestone 9): before a dirty page with
/// pageLSN = L is written out, flush_until(L) must succeed.
pub trait LogFlusher: Send + Sync {
    fn flush_until(&self, lsn: Lsn) -> Result<()>;
}

#[derive(Clone, Copy, Debug, Default, PartialEq, Eq)]
pub struct BufferPoolStats { pub hits: u64, pub misses: u64 }
impl BufferPoolStats { pub fn hit_rate(&self) -> f64; }

pub struct BufferPoolManager { /* frames: Vec<RwLock<Page>>, meta: Mutex<PoolMeta>, disk, log */ }
impl BufferPoolManager {
    pub fn new(pool_size: usize, disk: DiskManager, replacer: Box<dyn Replacer>) -> Self;
    pub fn set_log_flusher(&self, log: std::sync::Arc<dyn LogFlusher>); // wired in MS9
    pub fn fetch_page_read(&self, id: PageId) -> Result<ReadPageGuard<'_>>;   // shared latch + pin
    pub fn fetch_page_write(&self, id: PageId) -> Result<WritePageGuard<'_>>; // exclusive latch + pin
    pub fn new_page(&self) -> Result<(PageId, WritePageGuard<'_>)>;           // allocate + pin
    pub fn flush_page(&self, id: PageId) -> Result<()>;
    pub fn flush_all(&self) -> Result<()>;
    pub fn dirty_pages(&self) -> Vec<(PageId, Lsn)>;                          // MS9 DPT snapshot
    pub fn stats(&self) -> BufferPoolStats;
    pub fn pool_size(&self) -> usize;
}
impl ferricdb_storage::PageStore for BufferPoolManager { /* via Read/WritePageGuard */ }

/// RAII shared pin + read latch. Deref -> &Page; Drop releases latch then unpins.
pub struct ReadPageGuard<'a> { /* pool ref, frame, Option<RwLockReadGuard<'a, Page>> */ }
/// RAII exclusive pin + write latch. Deref/DerefMut -> Page; DerefMut marks dirty;
/// Drop releases latch then unpins.
pub struct WritePageGuard<'a> { /* pool ref, frame, dirty, Option<RwLockWriteGuard<'a, Page>> */ }

Provided wiring you should keep

Inspect crates/buffer/src/lib.rs before editing. Three pieces are already scaffolded for you: BufferPoolStats::hit_rate, BufferPoolManager::set_log_flusher and pool_size, and the full impl PageStore for BufferPoolManager at the bottom of the file. Notice how PageStore delegates directly to your new guards:

  • with_page calls fetch_page_read(id)? and passes &guard to the closure — reads acquire a shared latch and never mark the frame dirty.
  • with_page_mut calls fetch_page_write(id)? and passes &mut guard to the closure — invoking DerefMut sets the guard's dirty flag automatically.
  • allocate_page calls new_page()?, drops the returned guard immediately (leaving the fresh zeroed page resident and evictable), and returns its PageId.

Semantic requirements

Every behavior below is pinned by one or more tests in crates/buffer/tests/buffer.rs:

  • Resident hit (zero disk I/O). When id is in page_table, both fetch_page_read and fetch_page_write increment pin_count, mark the frame non-evictable on the 0 → 1 edge, record the access in the replacer, increment stats.hits, and return the guard without touching DiskManager. FerricDB is a write-back cache: mutations stay buffered until eviction or explicit flush.14
  • Miss & dirty-victim write-back. When id is absent, claim a free frame or ask replacer.evict() for a victim; if none exists, return Err(Error::BufferPoolExhausted) immediately — never block and never evict a pinned frame.1 If the victim is dirty, call LogFlusher::flush_until(page.lsn()) (when installed) and write the victim back before removing its mapping and reading id from disk. Install the new mapping, pin at 1, clear dirty/rec_lsn, record access, and increment stats.misses.1
  • new_page. Reuses the same free/evict path, allocates a fresh PageId from DiskManager, zeroes the frame, pins it, and returns (PageId, WritePageGuard). When every frame is pinned, fail with Error::BufferPoolExhausted before allocating on disk.
  • ReadPageGuard vs. WritePageGuard. Multiple threads may hold ReadPageGuards on the same page concurrently; WritePageGuard takes an exclusive latch. Calling DerefMut sets the guard's dirty flag; dropping an unmutated write guard leaves a clean frame clean.1
  • flush_page / flush_all. Write resident dirty frames to disk (honoring LogFlusher first) and clear their dirty flags without evicting them. Flushing a clean or non-resident page is a no-op.
  • dirty_pages() (Milestone 9 hook). Remains stubbed for Milestone 9, when ARIES checkpoints snapshot every resident dirty page's (PageId, rec_lsn); tracking an optional rec_lsn per frame today makes that hook effortless later.
  • ClockReplacer & LruKReplacer (stretch). CLOCK sets a frame's reference bit on access, skips non-evictable frames, clears set bits on sweep, and evicts the first evictable frame with a clear bit.23 LruKReplacer ranks evictable frames by largest backward k-distance (time since the k-th most recent access): frames with fewer than k accesses have +∞ distance and evict first, breaking ties FIFO by earliest recorded access.2

Safe-Rust concurrency & latch ordering

Why does BufferPoolManager hold frames: Vec<RwLock<Page>> outside meta: Mutex<PoolMeta>, and why are there two guard types instead of one? Understanding this architecture before writing code saves hours of debugging under ms2_stress_multithreaded.

Consider what goes wrong with naive single-lock designs in safe Rust:

  • You cannot return &Page or &mut Page from inside a Mutex<PoolMeta> without keeping the pool-wide mutex locked for the entire lifetime of the guard. If a thread holds the pool mutex while a guard is alive, the very next fetch_page_read — even on the same thread in ms2_concurrent_readers_share_page — immediately deadlocks!
  • You cannot store raw pointers to frames and cast them to &mut Page on demand without unsafe code, and two threads fetching the same page concurrently would create aliasing &mut references — instant undefined behavior in Rust.5

Putting each 8 KB Page in its own RwLock<Page> inside a fixed-length Vec<RwLock<Page>> solves both problems in 100% safe Rust and mirrors both CMU 15-445 BusTub's ReadPageGuard/WritePageGuard1 and PostgreSQL's separation of buffer-table/descriptor spinlocks from per-buffer shared/exclusive content locks.3 Meanwhile, keeping the page table, frame metadata, free list, stats, and the Replacer inside the single PoolMeta Mutex guarantees that page-table updates, pin-count edges, and replacer state transitions are always atomic with respect to one another — eliminating any possibility of lock-ordering bugs between the page table and the replacer.

The lock/drop ordering invariant (read twice)

Two locks exist on every fetch: the pool latch (self.meta) and the frame latch (self.frames[frame]). To guarantee freedom from ABBA deadlocks, every code path in BufferPoolManager must obey one invariant: never acquire self.meta while holding any frame's RwLock guard.3

  1. Fetch path: lock self.meta → look up or install the page and increment pin_count (marking the frame non-evictable on 0 → 1) → drop the MutexGuard<PoolMeta> → acquire self.frames[frame].read() (for fetch_page_read) or self.frames[frame].write() (for fetch_page_write). Because pin_count > 0 was recorded before releasing meta, no other thread can evict frame in the tiny window between dropping meta and acquiring the frame latch.
  2. Eviction path (inside meta): when a miss evicts a victim frame returned by replacer.evict(), that victim is guaranteed to have pin_count == 0. Because every guard drops its frame latch before re-locking meta to decrement pin_count to zero, no live guard holds self.frames[victim]! Therefore acquiring self.frames[victim].write() while holding meta during miss/eviction I/O cannot block on any guard holder and cannot deadlock.
  3. Drop path (the Rust drop-order trap): in Rust, a struct's Drop::drop(&mut self) runs before the compiler automatically drops the struct's fields. That is why both ReadPageGuard and WritePageGuard wrap their RwLock*Guard in an Option! Inside Drop::drop you must extract any needed value (for WritePageGuard, read page.lsn() if self.dirty), then call drop(self.guard.take()); first — releasing the frame's RwLock — and only afterward lock self.pool.meta to update dirty / rec_lsn, decrement pin_count, and call replacer.set_evictable(self.frame, true) when pin_count reaches 0. Skip self.guard.take(), and your guard holds the frame latch while trying to lock meta — reversing the lock order and risking deadlock the moment another thread locks meta and touches a frame.
  4. Flush path (flush_page / flush_all): if you flush a resident page that might currently be pinned by another thread, do not hold self.meta while calling self.frames[frame].read()! Keep a per-frame dirty_gen: u64 counter (incremented whenever a WritePageGuard marks the frame dirty on drop). Lock meta, verify the page is resident and dirty, snapshot its dirty_gen, temporarily pin the frame (so it cannot be evicted), and drop meta. Next acquire self.frames[frame].read(), call LogFlusher::flush_until(page.lsn()) if present, write the page to disk, and drop the read guard — capturing any Result without returning early so you always re-lock meta to decrement the temporary pin (preventing a pin leak on I/O error). On Ok(()), clear dirty and rec_lsn only if dirty_gen is still unchanged — if a concurrent writer dirtied the frame after you dropped the read guard, leaving dirty = true prevents eviction from discarding those newer changes. Now even a flush racing with an active writer obeys the exact same meta → drop → frame order without lost writes or leaked pins.

Step-by-step guidance

Build bottom-up and run the tests after every step. Pseudocode below covers the published replacement algorithms; all Rust implementation details remain yours.

  1. Implement ClockReplacer in isolation first. Store three small fields: ref_bits: Vec<bool>, evictable: Vec<bool>, hand: usize, plus evictable_count: usize (so evictable_count() is O(1)). Bounds-check or assert frame < num_frames. Make set_evictable idempotent: only increment/decrement evictable_count when the boolean actually changes. The textbook CLOCK sweep:3 
    evict():
    if evictable_count == 0:
        return None
    loop:
        f ← hand
        hand ← (hand + 1) mod num_frames
        if not evictable[f]:
            continue                         // pinned frames are invisible
        if ref_bits[f]:
            ref_bits[f] ← false              // second chance
        else:
            evictable[f] ← false
            evictable_count ← evictable_count − 1
            return Some(f)
    Trace Figure 3 against this loop by hand — every bit flip and hand position must match — and run ms2_clock_evicts_unpinned before touching BufferPoolManager.
  2. Define PoolMeta and per-frame descriptors. Keep one private descriptor per frame recording its resident Option<PageId>, pin_count, dirty flag, and Option<Lsn> recovery LSN. Put the descriptor vector, page_table, free_list, replacer, and BufferPoolStats together inside PoolMeta, extending the initializer already started in BufferPoolManager::new.
  3. Factor one private frame-pinning helper shared by both fetch methods. fetch_page_read(id) and fetch_page_write(id) share the exact same hit/miss state machine under self.meta and differ only in whether they lock self.frames[frame] for reading or writing after releasing meta. On a miss, take a frame from free_list or replacer.evict(); if the victim is dirty, enforce LogFlusher and write it to disk before evicting its old table entry and reading id. Watch the error path: if disk.read_page fails (for example, InvalidPage), return the claimed frame to free_list so invalid fetches never leak frames.
  4. Implement new_page using the same victim selection. Claim a free or evicted frame first (returning BufferPoolExhausted before touching the disk if all frames are pinned), allocate the new PageId, zero the frame's Page, install its table entry with pin_count = 1, drop meta, and return (new_id, WritePageGuard).
  5. Finish ReadPageGuard::drop and WritePageGuard::drop. In WritePageGuard::drop: if self.dirty is true, read the page's current LSN while the guard is still present, then explicitly release the frame latch via drop(self.guard.take()) before locking self.pool.meta to merge the dirty flag (setting rec_lsn on the clean-to-dirty transition), decrement pin_count, and flip the frame evictable on the 1 → 0 edge. ReadPageGuard::drop releases its read latch first and unpins without touching dirty state. Never panic inside Drop: a double panic during unwinding aborts the whole test binary.
  6. Implement flush_page, flush_all, and stats. Channel every dirty write (eviction, flush_page, and flush_all) through one private helper that clones the optional Arc<dyn LogFlusher> out of self.log, drops the log mutex, calls flush_until(page_lsn), and writes the page to disk. Follow the pin-then-drop pattern from the concurrency section so flushing never holds meta while waiting on a frame latch.
  7. Run the core suite, then hammer the stress test. Pass the seven single-threaded core tests first, then run ms2_stress_multithreaded at least five times in a row. If it fails or hangs, reproduce with 2 threads, 2 frames, and 3 pages — latching and pin-count bugs surface immediately at tiny sizes.
  8. Wire the REPL to your buffer pool. In course/ferricdb/crates/ferricdb/src/repl.rs, wrap the opened DiskManager in an Arc<BufferPoolManager> (64 frames with ClockReplacer::new(64) — 512 KB, a course choice matching DEFAULT_MEMORY_PAGES) and call flush_all() on clean exit and before .open <path> switches databases.
  9. Stretch goal — LruKReplacer. Keep a monotonic logical clock and a bounded queue of the last k access timestamps per frame. On evict(), prefer evictable frames with fewer than k accesses (infinite backward k-distance), breaking ties among them FIFO by oldest recorded timestamp; otherwise pick the evictable frame with the smallest k-th most recent timestamp (largest backward k-distance), clearing the victim's history on eviction.2 Verify against stretch_lruk_backward_distance: for k = 2 and accesses A(t1), B(t2), B(t3), C(t4), A(t5), D(t6), the < 2 frames C (t4) and D (t6) evict first in FIFO order, then A (2nd-most-recent t1 < B's t2), then B.

Understanding the hit-rate benchmark

crates/buffer/benches/hit_rate.rs allocates 256 pages over a 64-frame pool (a working set 4× larger than RAM) and runs a 1,120-fetch skewed access pattern: 80% of fetches (896) hit 32 hot pages ((i * 13) % 32), while 20% (224 fetches, whenever i % 5 == 0) walk all 224 cold pages using effective stride 85 (32 + (i * 17) % 224 — gcd(85, 224) = 1, so every cold page is touched once per pass). Before timing the Criterion loop, the benchmark prints the exact observed hit rate computed from your pool.stats() counters (expect roughly ~80% hits with CLOCK, since the 32 hot pages keep their reference bits set and stay resident while the cold scan cycles through the remaining 32 frames). Record both the printed hit rate and the Criterion iteration time in your notes — if you implement LruKReplacer, swap it in locally to see how backward 2-distance resists scan pollution.

Common pitfalls

Pitfall — forgetting drop(self.guard.take()) in Drop

Symptom: single-threaded tests pass, then ms2_stress_multithreaded freezes permanently (test hangs until you press Ctrl-C). Cause: Rust drops struct fields after Drop::drop finishes. If Drop::drop locks self.pool.meta while self.guard still holds RwLockReadGuard or RwLockWriteGuard, your thread holds a frame latch while waiting for meta — the exact inverse of the eviction path. Fix: extract lsn if dirty, call drop(self.guard.take()) explicitly, and only then lock meta.

Pitfall — evicting a pinned page (wrong pin-count edge)

Symptom: intermittent assertion failures in ms2_stress_multithreaded where a thread reads a stale counter value that does not match its round number. Cause: calling set_evictable(frame, true) on every unpin instead of only when pin_count drops to 0, or forgetting set_evictable(frame, false) when a resident page transitions from 0 → 1. Fix: drive evictability strictly from pin-count transitions (0 → 1 sets false; 1 → 0 sets true) inside the same PoolMeta critical section.2

Pitfall — dropping a dirty victim or forgetting the WAL hook

Symptom: ms2_fetch_roundtrip_through_eviction reads back zeros instead of the byte stamped before eviction, or Milestone 9's recovery test fails because a dirty page reached disk ahead of its log record. Cause: overwriting the victim's frame bytes without checking fm.dirty first, or writing without calling LogFlusher::flush_until(page.lsn()). Fix: channel every disk write (eviction, flush_page, flush_all) through one private helper that enforces the log flusher before calling disk.write_page.1

Pitfall — leaking a frame when disk.read_page returns Err

Symptom: calling fetch_page_read(9999) on a non-existent page returns Err(InvalidPage), and after pool_size bad fetches the entire pool permanently returns BufferPoolExhausted. Cause: you popped a frame from free_list (or evicted a victim), then used ? on disk.read_page before returning the frame to free_list. Fix: if read_page fails after evicting the old mapping, clear the frame's metadata and push frame back onto free_list before returning the error.

Pitfall — marking a frame dirty on fetch_page_write instead of DerefMut

Symptom: unnecessary disk writes on read-only paths that happen to take a write guard, or ms2_resident_fetch_does_no_io failing if a reader marks the frame dirty and triggers an unwanted write. Cause: setting dirty = true eagerly at fetch time. Fix: initialize WritePageGuard { dirty: false, .. } and set self.dirty = true inside DerefMut::deref_mut — the single choke point where mutation becomes possible.1

Definition of done

  • All eight core ms2_ tests in ferricdb-buffer pass using cargo test -p ferricdb-buffer -- --include-ignored ms2_ (and --include-ignored stretch_lruk passes if you also completed the LruKReplacer stretch goal).
  • ms2_stress_multithreaded passes at least five consecutive runs with zero hangs and zero failures.
  • ms2_pagestore_impl_serves_heapfile passes, proving Milestone 1's HeapFile runs unmodified over your BufferPoolManager.
  • cargo bench -p ferricdb-buffer runs cleanly and you have recorded both the printed hit_rate percentage and Criterion throughput in your notes.
  • crates/ferricdb/src/repl.rs uses Arc<BufferPoolManager> (with flush_all() on exit and before .open) instead of raw DiskManager.
  • You can explain, without notes, why ReadPageGuard::drop must call drop(self.guard.take()) before acquiring self.pool.meta.
