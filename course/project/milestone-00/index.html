SQLite's tutorial-clone lineage starts every build-a-database project the same way: with a REPL — read a line, decide whether it is a command for the shell or a statement for the engine, loop.1 There is a reason. The shell is the harness you will live in for the next ten milestones: every layer you build gets poked from this prompt minutes after it compiles. This milestone is deliberately light on database theory — it is about owning your tools before the real work starts.

Learning objectives

  • Navigate the FerricDB workspace: what each crate owns, what is provided, what is stubbed, and how the crates depend on each other.
  • Implement an interactive REPL with rustyline: line editing, history, and a meta-command dispatcher.2
  • Explain the front-end/engine split — why meta-commands are dispatched before SQL ever reaches a parser.1
  • Operate the provided test inventory: run it, list what is ignored, and un-ignore a milestone group on purpose.
  • Wire CI so fmt, clippy, and the test suite gate every change.

Where this fits

Specification

The workspace at course/ferricdb/ is provided: the root manifest pins the allowed dependencies, crates/common ships fully implemented (values, schemas, errors — run its tests now), and every other crate declares its public API as documented stubs. Your work lives in crates/ferricdb:

// crates/ferricdb/src/repl.rs — the surface you implement
// (signatures from the workspace API contract, docs/api-spec.md;
// the stub file has the full doc comments)

/// Interactive shell: reads SQL lines / meta-commands, prints result tables.
/// Meta-commands: .help  .exit  .tables  .schema <table>  .ast <sql>  .open <path>
pub struct Repl { /* ExecContext + rustyline editor */ }

impl Repl {
    pub fn new(db_path: Option<&Path>) -> Result<Self>;
    pub fn run(&mut self) -> Result<()>;
}

// crates/ferricdb/src/main.rs — already sketched:
// ferricdb [--db <path>] [--serve [addr]]     (--serve activates in MS10)

Behavior contract for this milestone:

  • Lines starting with . are meta-commands, dispatched before any SQL handling — the same split SQLite's shell makes.1 Unknown meta-commands print an error and a pointer to .help.
  • .help lists all six meta-commands with one-line descriptions.
  • .exit ends the session cleanly; so do Ctrl-D (EOF) and Ctrl-C at an empty prompt.
  • .tables and .schema will read the catalog from Milestone 3 onward; today they print a friendly "no catalog yet" message.
  • .ast activates in Milestone 3 (it pretty-prints the parse tree); .open switches the database file once storage exists in Milestone 1.
  • Anything else is a statement: for now, echo it back with a note that execution arrives in Milestone 4. Statements may span lines until a terminating ; — build that buffering now and the parser slots in later without touching the loop.

Step-by-step guidance

  1. Tour before you type. cargo test --workspace — green, with a long list of ignored tests. That list is the course contents in test form: cargo test --workspace -- --list --ignored. Skim crates/common's source; you own its types (Value, Schema, RecordId) from here on.
  2. Parse the flags by hand. A small loop over std::env::args() is enough for --db and --serve; the course crate policy leaves no room for an argument-parsing dependency, and you will not need one.
  3. Build the loop. Construct the rustyline editor in Repl::new, then loop on readline("ferricdb> "). Match the three outcomes explicitly: a line, Interrupted, Eof.2 Feed every accepted line into the editor history.
  4. Dispatch on the first byte. Trim, skip empty lines, and route .-prefixed input to a match over the command word. Keep the dispatcher a pure function from input string to a small MetaCommand enum — it makes the smoke tests trivial.
  5. Buffer statements until ;. Keep a pending-statement string; show a continuation prompt ( ...> ) while it is non-empty. This is exactly how psql behaves, and your muscle memory will thank you.
  6. Print through one function. Route all output through a print_result helper now, even though it only echoes today — in Milestone 4 it grows column-aligned result tables and you will not have to hunt for print sites.
  7. Turn on CI. The provided workflow file runs cargo fmt --check, clippy, and the test suite. Push a branch, watch it go green, and keep it green for the rest of the course.

Test plan

ferricdb> .exit

Common pitfalls

Meta-commands routed through the SQL path

If .help reaches the (future) parser you will "fix" it in Milestone 3 by special-casing the lexer — the wrong place. Dispatch on the leading dot before anything else touches the line; the shell language and SQL are different languages.1

Ctrl-C kills the process

rustyline surfaces Ctrl-C as ReadlineError::Interrupted, not a signal you can ignore. Swallow it at an empty prompt, clear the pending statement buffer at a continuation prompt — never std::process::exit from inside the loop.2

Skipping the workspace tour

Learners who jump straight to code discover in Milestone 2 that they re-implemented a type common already provides. Twenty minutes reading crates/common and the stub rustdoc now saves hours later.

Definition of done

  • REPL starts with and without --db, echoes multi-line statements terminated by ;, and exits cleanly on .exit, Ctrl-D, and double Ctrl-C.
  • All six meta-commands respond (.tables/.schema/.ast/ .open with their honest "not yet" messages).
  • cargo test --workspace, cargo fmt --check, and cargo clippy are green locally and in CI.
  • You can name, from memory, which crate you will touch in each of the next three milestones.
