Stretch pages are deliberately lower-detail than core milestones: a spec, a design sketch, and pointers — the details are yours to engineer.

The goal

Milestone 8 shipped with the course's most honest test: ms8_write_skew_is_documented asserts that the write-skew anomaly succeeds under your snapshot isolation, exactly as toyDB documents for its own MVCC.2 This stretch flips that test: add a SERIALIZABLE isolation mode under which the same scenario aborts one transaction with a serialization error, while plain snapshot isolation mode keeps its current behavior.

Why SI admits write skew — and how SSI catches it

First-committer-wins compares write sets; write skew's transactions write disjoint rows, so it sails through. What the anomaly does leave behind is a distinctive dependency shape: each transaction reads data the other writes — a pair of read-write (rw) antidependencies between concurrent transactions. Serializable Snapshot Isolation detects this pattern instead of preventing it with blocking: PostgreSQL's Serializable level keeps non-blocking predicate locks that record which reads a concurrent write would have affected, and aborts a transaction (SQLSTATE 40001, retry) when a dangerous structure completes — with the documented cost that monitoring dependencies and restarting transactions isn't free.1 Your simplified version follows the same philosophy with cruder bookkeeping: track read sets, detect rw-antidependencies at commit, and abort conservatively — more false positives than real SSI is an acceptable trade at course scale, and you should state it in your rustdoc the way toyDB states its own limitations.2

Where this fits

Suggested design

Extensions to crates/txn — a suggested shape, not a provided stub:

pub enum IsolationLevel { Snapshot, Serializable }

impl TransactionManager {
    pub fn begin_with(&self, level: IsolationLevel) -> Arc<Transaction>;
    /// Called by scans under Serializable: remember what this txn read.
    pub fn record_read(&self, txn: &Transaction, rid: RecordId);
}
// commit(): in addition to first-committer-wins, under Serializable abort if
//   my read set ∩ writes of concurrent committed txns ≠ ∅   (rw into the past)
//   or my write set ∩ reads of concurrent committed txns ≠ ∅ (rw into me)

That commit rule is deliberately stronger than true SSI (which aborts only when two rw-antidependencies form a dangerous structure); the stronger rule is simpler, still correct (never admits a non-serializable history), and only costs extra aborts.

Build plan

  1. Add the isolation level to begin, the REPL (BEGIN SERIALIZABLE), and the session default.
  2. Thread record_read through SeqScan and IndexScan — only for rows actually returned to the transaction, only under Serializable.
  3. Keep read sets alongside the write sets you already store; extend the commit-time check under the same lock.
  4. Write the flip test: the M09 doctors scenario aborts one transaction under Serializable and completes under Snapshot — both asserted.
  5. Add a no-false-positive guard: two serializable transactions touching disjoint data must both commit.

Pitfalls

Conflating write-write with read-write conflicts

First-committer-wins already handles write-write. If your new check only compares write sets harder, write skew still escapes — the whole point is the read sets.

Predicate reads

Tracking read rows misses phantom-flavored skew: a transaction that read "no row matched WHERE x > 10" read a predicate, not a row, and a concurrent insert into that range escapes row-granularity tracking. Real SSI predicate-locks the range;1 acknowledge the gap in your rustdoc, or coarsen to table-granularity reads for DDL-free honesty.

Unbounded read sets

A serializable full-table scan records every row. Fine at course scale — but note the production answer (granularity promotion: row → page → table locks) so the design reads as a choice, not an oversight.

Definition of done

  • The write-skew scenario aborts one transaction with a serialization error under SERIALIZABLE and still succeeds under plain snapshot isolation — both tested.
  • Disjoint serializable transactions commit without false aborts (simple cases).
  • All ms8_ tests still pass in Snapshot mode; the documented-anomaly test is updated to run under Snapshot explicitly.
  • Your rustdoc states the simplifications (row-granularity reads, conservative aborts) and cites what real SSI adds.
