Milestone 3 is the widest milestone in the course — three workspace crates receive real code: ferricdb-sql, ferricdb-catalog, and the binder module inside ferricdb-exec. Unlike Milestone 2, none of this code fights multi-threaded latching or raw byte alignment, so each piece tests cleanly in isolation and builds steady momentum. By the end, the REPL stops echoing raw strings: .ast SELECT 1 + 2 * 3; renders a parse tree, CREATE TABLE writes catalog rows into heap pages through your Milestone 2 buffer pool, .tables and .schema inspect them across restarts, and the binder rejects bad columns and type errors before execution even exists.

Learning objectives

  • Implement a hand-written SQL lexer covering case-insensitive keywords, lowercase-folded identifiers, -- line comments, '' string escaping, and greedy maximal-munch two-character operators.
  • Implement a recursive-descent statement parser paired with an 8-level Pratt expression parser — matching the sqlparser-rs design and contrasting with SQLite's Lemon-generated parser.13
  • Design and implement a self-hosted Catalog whose own __tables and __columns tables live in heap pages behind a fixed page-0 bootstrap header, mirroring PostgreSQL's compiled-in catalog bootstrap.5
  • Implement the Binder that resolves table and column names to (table_idx, col_idx) pairs, checks types bottom-up with implicit Integer → Float widening, and rejects invalid queries with descriptive Error::Bind messages.2
  • Wire the REPL end-to-end across DiskManager → BufferPoolManager → Catalog for .open, .tables, .schema, .ast, and persistent DDL.4

Required reading

  • M05 · SQL Front-End — the concept module covering lexing, recursive descent, Pratt parsing with a worked trace, AST design, and the binder contract.
  • apache/datafusion-sqlparser-rs — Pratt/TDOP expression parsing inside hand-written recursive descent, the architecture FerricDB reproduces.1
  • Hironobu Suzuki, The Internals of PostgreSQL, §3.1 — how PostgreSQL separates a schema-free parser from a catalog-backed analyzer (our binder).2
  • PostgreSQL Documentation, “System Catalogs” — pg_class and pg_attribute, the production ancestors of __tables and __columns.5
  • SQLite, “Architecture of SQLite” and cstack, Part 2 — two contrasting front-end/engine splits (SQLite's generated parser targeting bytecode; cstack's minimal metacommand vs. statement preparation boundary).34

Grammar & 8-level Pratt precedence

Exact lexical and syntactic rules pinned by crates/sql/src/lib.rs and crates/sql/tests/parser.rs:

Lexical rules

  • Whitespace & comments: ASCII whitespace separates tokens and is discarded. -- starts a line comment discarding everything up to the next \n or end of input (distinct from single -, which lexes as Token::Minus).
  • Keywords vs. identifiers: words matching [a-zA-Z_][a-zA-Z0-9_]* are matched case-insensitively against Keyword (SELECT, select, and SeLeCt all produce Token::Keyword(Keyword::Select)). Non-keyword words become Token::Ident folded to lowercase (matching PostgreSQL's unquoted identifier folding; quoted identifiers are not part of the course grammar). TRUE and FALSE (any case) lex directly to Token::BoolLit(bool); NULL stays Keyword::Null because it appears both as a literal and inside NOT NULL / IS [NOT] NULL.
  • Literals: single-quoted strings '...' preserve interior case and unescape doubled quotes '' to a single ' (SQL standard, not \'). Digit runs lex to Token::IntegerLit(i64) (a leading - is never consumed as part of the literal — it is always Token::Minus); digits.digits lexes to Token::FloatLit(f64).
  • Maximal munch & errors: two-character operators (<=, >=, <>, !=) are matched greedily before single-character ones; both <> and != produce Token::NotEq. Token carries no source positions in this course (error messages quote the offending text instead). Unterminated strings, i64 overflow, a lone !, or unrecognized characters (#, @) return Err(Error::Parse(...)) and never panic.

Statement grammar (Milestone 3 scope)

script       := { ";" } [ statement { ";" { ";" } statement } ] { ";" }
statement    := create_table | drop_table | insert | select | update | delete
              | "BEGIN" | "COMMIT" | "ROLLBACK"

create_table := "CREATE" "TABLE" ident "(" column_def { "," column_def } ")"
column_def   := ident type { "PRIMARY" "KEY" | "NOT" "NULL" | "NULL" }
type         := "BOOLEAN" | "INT" | "INTEGER" | "FLOAT" | "DOUBLE" | "TEXT" | "VARCHAR"
drop_table   := "DROP" "TABLE" ident

insert       := "INSERT" "INTO" ident [ "(" ident { "," ident } ")" ]
                "VALUES" "(" expr { "," expr } ")" { "," "(" expr { "," expr } ")" }

select       := "SELECT" select_item { "," select_item }
                [ "FROM" table_ref { "," table_ref } ]
                [ "WHERE" expr ]
                [ "ORDER" "BY" expr [ "ASC" | "DESC" ] { "," expr [ "ASC" | "DESC" ] } ]
                [ "LIMIT" integer_literal ]
select_item  := "*" | expr [ "AS" ident ]
table_ref    := ident [ [ "AS" ] ident ]       // JOIN clauses arrive in MS6

update       := "UPDATE" ident "SET" ident "=" expr { "," ident "=" expr } [ "WHERE" expr ]
delete       := "DELETE" "FROM" ident [ "WHERE" expr ]

Key grammar details tested directly in parser.rs:

  • Multi-statement scripts: Parser::parse skips empty and stray semicolons ("" and " ; ; " return Ok(vec![]); "BEGIN; COMMIT;" returns two statements).
  • Type synonyms & PRIMARY KEY: INT/INTEGER → DataType::Integer, FLOAT/DOUBLE → DataType::Float, TEXT/VARCHAR → DataType::Text, BOOLEAN → DataType::Boolean. Column options may appear in any order after the type, and PRIMARY KEY always implies nullable: false.
  • Optional FROM and wildcard: SELECT 1 + 1 parses with from: vec![]; SELECT * FROM t produces vec![SelectItem::Wildcard]; ORDER BY defaults to ascending (desc: false); comma-separated FROM a, b keeps separate entries in Select::from.
  • Functions & COUNT(*): function calls lowercase-fold the function name, and COUNT(*) parses as Expr::Function("count".into(), vec![]) — ready for Milestone 6 aggregates.
  • Standalone expressions: Parser::parse_expr parses one expression and rejects any trailing unconsumed tokens ("1 + 2 3" must return Err(Error::Parse)).

Unified 8-level Pratt binding-power table

Your Pratt expression parser must match the exact binding-power table declared in crates/sql/src/ast.rs and lib.rs (higher number binds tighter; every infix operator is left-associative, recursing on its right-hand side with bp + 1):1

Power Fixity Operators RHS min_bp / grouping example
1 Infix (left) OR 2 — a OR b AND c ⇒ a OR (b AND c)
2 Infix (left) AND 3 — NOT a AND b ⇒ (NOT a) AND b
3 Prefix NOT 3 — NOT active IS NULL ⇒ NOT (active IS NULL)
4 Postfix IS NULL, IS NOT NULL — — a = 1 IS NULL ⇒ (a = 1) IS NULL
5 Infix (left) =, <>, !=, <, <=, >, >= 6 — a + 1 > b ⇒ (a + 1) > b
6 Infix (left) +, - 7 — a - b - c ⇒ (a - b) - c
7 Infix (left) *, /, % 8 — 1 + 2 * 3 ⇒ 1 + (2 * 3)
8 Prefix - (unary negation) 8 — -x + 1 ⇒ (-x) + 1, -2 * 3 ⇒ (-2) * 3
9 (atom) Primary literals, [qual.]col, CAST(e AS t), fn(args), COUNT(*), (e) Parentheses reset min_bp = 0 and vanish from the AST.

Catalog bootstrap & binder design

Self-hosted catalog bootstrap (pages 0, 1, and 2)

A real database does not keep its table definitions in a sidecar JSON file — it stores them inside the database file itself so one page store, one buffer pool, and (later) one WAL cover everything. That creates an apparent chicken-and-egg problem: to read the schema of table users, you scan the __tables and __columns tables, but how do you know the schema and page location of __tables and __columns? PostgreSQL breaks the circle with compiled-in bootstrap descriptors for pg_class and pg_attribute.5 FerricDB uses the same pattern with three fixed page ids:

  • Page 0 — Catalog Header Page: an 8 KB page that preserves the universal 16-byte reserved page header at bytes 0..16 (pageLSN, page_type, reserved — required so Milestone 9's buffer-pool LogFlusher::flush_until(page.lsn()) never reads magic bytes as an LSN), followed at byte offset 16 by an 8-byte magic/version tag (e.g. b"FRDBCAT1" at 16..24), next_oid: u32 (24..28), tables_first_page: PageId (= 1, 28..32), columns_first_page: PageId (= 2, 32..36), plus two reserved PageId slots for indexes_first_page (Milestone 5, 36..40) and stats_first_page (Milestone 7, 40..44), initialized to INVALID_PAGE_ID. Reserving those two 4-byte slots on Page 0 today means Milestones 5 and 7 can add __indexes and __stats heap files without changing the database file format.
  • Page 1 — __tables HeapFile: compile-time constant schema (oid INTEGER, name TEXT, first_page INTEGER).
  • Page 2 — __columns HeapFile: compile-time constant schema (table_oid INTEGER, ordinal INTEGER, name TEXT, type_tag INTEGER, nullable BOOLEAN), where type_tag maps Boolean=0, Integer=1, Float=2, Text=3.

Catalog::bootstrap(store) inspects store.num_pages(). On a fresh store (num_pages() == 0), it allocates pages 0, 1, and 2 in order, writes the Page 0 header with next_oid = 1, initializes pages 1 and 2 via HeapPage::init, and returns an empty CatalogCache. On an existing store (num_pages() > 0), it reads and validates Page 0's magic tag, scans __tables and __columns through ordinary HeapFile::open iterators, groups columns by table_oid sorted by ordinal, and rebuilds CatalogCache. One invariant trips up many first drafts: Catalog::tables() must return user tables only — never __tables or __columns. On a freshly bootstrapped database, catalog.tables()? must return an empty Vec.

Binder responsibilities & implicit numeric widening

The parser knows syntax but not schemas; the binder (crates/exec/src/binder.rs) plays PostgreSQL's analyzer role — checking every name and type against Catalog and producing a BoundStatement whose executor never has to touch string column names again:2

  • FROM-list flattening & scope table: walk Select::from left to right, assigning each base table an incrementing table_idx (0, 1, …) and recording its exposed qualifier (alias if given, else table name) alongside its TableInfo.
  • Qualified vs. unqualified lookup: for q.col, find the scope entry matching q and look up col in its schema. For unqualified col, search every scope entry: 0 matches ⇒ Err(Error::Bind) naming the missing column; 2+ matches ⇒ Err(Error::Bind) reporting an ambiguous column; 1 match ⇒ BoundExpr::Column { table, column, data_type }.
  • Wildcard expansion & aliases: expand SelectItem::Wildcard into every column of every table in scope in FROM-list order. Output column names follow the alias if present, else the column name, else a synthesized name (e.g. col0).
  • Bottom-up type checking & implicit Integer → Float widening: infer the Option<DataType> of each expression (None for bare Value::Null). Arithmetic operators require numeric operands; if one side is Integer and the other is Float, implicitly widen the integer to Float (for example by wrapping it in BoundExpr::Cast(expr, DataType::Float)) and infer Float. Comparisons require compatible types (same type, Integer/Float with numeric widening, or NULL) and yield Boolean. Notice why numeric widening matters immediately: ms3_binder_resolves_and_rejects binds WHERE score > 10 where score is FLOAT and 10 is INTEGER, and Milestone 6 inserts integer literals into a FLOAT column!
  • Statement-level checks: reject non-boolean WHERE predicates (WHERE id fails with Error::Bind); reject INSERT row arity mismatches, unknown target columns, omitted NOT NULL columns, or incompatible value types (reordering explicit column lists into full table-schema order and filling omitted nullable columns with BoundExpr::Literal(Value::Null)); verify every UPDATE SET column exists and matches its expression type (allowing Integer → Float); reject aggregate calls in Milestone 3 (Milestone 6 lowers them into AggExpr and BoundExpr::InputRef).

Step-by-step guidance

Tackle the three crates in order: sql → catalog → exec::binder → repl. Each layer compiles and tests independently before the next starts.

  1. Build Lexer::tokenize first. Walk the input with a Peekable<Chars> or byte/char index cursor. Handle whitespace and -- line comments in the outer loop, then dispatch on the current character: letter/_ → scan word, match uppercased against Keyword / TRUE / FALSE, else emit lowercase Ident; ' → scan string with '' unescaping (error on EOF); ASCII digit → scan digits, peeking for . followed by another digit to decide FloatLit vs. IntegerLit; two-char operators before one-char operators. Make all five ms3_lexer_* tests green in an hour.
  2. Build the token cursor and statement recursive descent. Wrap &[Token] in a private cursor struct with peek(), next(), eat(&Token), and expect(&Token). Remember: never advance past a token before checking it! Implement the outer parse loop skipping empty Semicolons, then dispatch on the leading Keyword: start with BEGIN/COMMIT/ROLLBACK, DROP TABLE, and CREATE TABLE (mapping type synonyms and folding PRIMARY KEY into nullable: false).
  3. Implement the Pratt expression core. Follow the classic Pratt / TDOP algorithm1 with your 8-level binding-power table: 
    parse_expr(min_bp):
    // 1. Prefix / primary position (nud)
    lhs ← match next token:
        NOT    → Unary(Not, parse_expr(3))
        '-'    → Unary(Neg, parse_expr(8))
        '('    → e ← parse_expr(0); expect(')'); e
        CAST   → expect('('); e ← parse_expr(0); expect(AS); t ← parse_type(); expect(')'); Cast(e, t)
        lit    → Literal(v)
        ident  → if peek == '(' → parse_func_call(ident)   // COUNT(*) → Function("count", [])
                 else if peek == '.' → consume '.'; Column(Some(ident), expect_ident())
                 else → Column(None, ident)

    // 2. Postfix & infix loop (led)
    loop:
        if peek == IS and 4 >= min_bp:
            consume IS; neg ← eat(NOT); expect(NULL)
            lhs ← IsNull(lhs, neg); continue
        if let Some((op, bp)) = infix_bp(peek):
            if bp < min_bp: break
            consume operator
            rhs ← parse_expr(bp + 1)         // left-associative
            lhs ← Binary(lhs, op, rhs)
        else: break
    return lhs
    Run all four expression-precedence tests (ms3_precedence_arithmetic, ms3_precedence_logic_and_comparison, ms3_left_associativity, ms3_unary_minus_is_null_cast_qualified) plus ms3_invalid_sql_errors_not_panics.
  4. Finish SELECT, INSERT, UPDATE, DELETE. In SELECT, parse clauses strictly in SQL order: projection list (handling * and optional AS alias), optional FROM, optional WHERE, optional ORDER BY (each key defaulting to desc = false), optional LIMIT. Verify all 17 ms3_ tests in ferricdb-sql pass before opening crates/catalog.
  5. Implement Catalog in crates/catalog. Define the compile-time schemas of __tables and __columns and the Page 0 header byte layout as private constants at the top of lib.rs. Use HeapFile::open and ferricdb_storage::tuple::{serialize, deserialize} for all catalog reads and writes — everything flows through Arc<dyn PageStore>, never raw DiskManager. In create_table: reject duplicate names with Error::Catalog, allocate the user table's heap via HeapFile::create, assign oid and persist updated next_oid to Page 0, insert rows into __tables and __columns, and update CatalogCache. In drop_table: verify the table exists, delete its matching rows from __tables and __columns via HeapFile::delete, and remove it from CatalogCache.
  6. Implement Binder::bind in crates/exec/src/binder.rs. Write a private bind_expr(&self, expr, scope) -> Result<(BoundExpr, Option<DataType>)> helper so type checking and column resolution happen in a single bottom-up pass. Ensure every error returns Error::Bind naming the offending table, column, or types (convert missing-table Error::Catalog lookups into Error::Bind so ms3_binder_resolves_and_rejects sees Err(Error::Bind(_))!).
  7. Wire the REPL (crates/ferricdb/src/repl.rs). Following cstack's clean metacommand-vs-statement dispatch boundary:4
    • On startup and on .open <path>, build DiskManager → Arc<BufferPoolManager> → Arc<Catalog> via Catalog::bootstrap (calling flush_all() on the previous store before switching files).
    • Implement .tables (list names from catalog.tables()), .schema <table> (print each column's name, type, and NOT NULL from catalog.table(name)), and .ast <sql> (call Parser::parse and pretty-print the AST).
    • For SQL input ending in ;, parse with Parser::parse and bind with Binder::new(&catalog). Execute BoundStatement::CreateTable and BoundStatement::DropTable directly against catalog (followed by store.flush_all() so DDL persists across restarts); for other valid bound statements, print a short status line noting execution arrives in Milestone 4.

Common pitfalls

Pitfall — precedence bugs around NOT and IS NULL

Symptom: NOT a AND b parses as NOT (a AND b), or a + 1 > b AND c groups incorrectly, or x IS NOT NULL fails to parse after a comparison. Cause: shifting a number in the 8-level table or forgetting to check postfix IS [NOT] NULL inside the Pratt led loop. Fix: copy the 8-level table verbatim (OR=1, AND=2, NOT=3, IS NULL=4, cmp=5, +/-=6, */%=7, neg=8) and verify every boundary with Parser::parse_expr.

Pitfall — returning __tables / __columns from Catalog::tables()

Symptom: ms3_bootstrap_create_table_roundtrip fails on its very first assertion (assert!(catalog.tables().unwrap().is_empty())), or .tables prints internal tables on a blank database. Cause: inserting rows describing __tables and __columns into __tables without filtering them out, or storing them in CatalogCache::tables. Fix: Page 0 points directly to pages 1 and 2; keep only user tables inside __tables and CatalogCache::tables.

Pitfall — forgetting to persist next_oid across reopen

Symptom: ms3_catalog_persists_across_reopen passes, then creating a new table after reopening collides with OID 1 and mixes two tables' columns together in __columns! Cause: initializing next_oid = 1 on reopen instead of reading it from Page 0 (or taking max_seen_oid + 1). Fix: write next_oid into Page 0 on every allocation and verify on reopen that next_oid exceeds every loaded OID.

Pitfall — returning Error::Catalog instead of Error::Bind from the binder

Symptom: ms3_binder_resolves_and_rejects fails on SELECT id FROM ghost with Err(Error::Catalog(...)) when the test asserts Err(Error::Bind(_)). Cause: using ? directly on self.catalog.table(&name)?, propagating Error::Catalog out of Binder::bind. Fix: map missing-table catalog errors to Error::Bind(format!("unknown table `{name}`")) inside the binder.

Pitfall — forgetting to flush the buffer pool after DDL in the REPL

Symptom: .tables shows your newly created table during the session, then vanishes the moment you restart ferricdb --db test.db. Cause: catalog pages modified in your write-back buffer pool were never flushed to disk. Fix: call store.flush_all()? after DDL statements and on clean REPL exit (until Milestone 9's WAL provides crash durability).

  • Malformed SQL and invalid column/table references produce readable error messages and never panic the REPL.
